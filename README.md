# tools

## デザイン共通ルール

- 新しいツールは `shared.css` を読み込み、Material Design を参考にした色・角丸・カード影・基本フォントを共通化します。
- 色や余白の基準を変える場合は、まず `shared.css` のカスタムプロパティを更新します。
- 各ツール固有のレイアウトや操作部品のスタイルは、そのツールのページに追加します。
- キーボードフォーカスを見える状態にし、狭い画面でも操作部品が使えるレイアウトにします。
- 各ツールのページ上部に、トップページへ戻れるパンくずリスト（`AIツールひろば › ツール名`）を置きます。リンク先は `../`、現在のページには `aria-current="page"` を付けます。

## SEO共通ルール

新しいツールを追加するとき、また既存のページを変更するときは、次をすべて満たします。

### head
- `<title>` は「ツール名 - 用途を表す短い説明｜AIツールひろば」の形にする（全体で35文字程度まで）
- `<meta name="description">` に、何ができるか、無料・登録不要であること、入力した内容が送信されないことを、80〜120文字で書く
- `<link rel="canonical">` に、そのページの絶対URL（`https://autotoolspublisher-ui.github.io/tools/フォルダ名/`）を書く
- `<link rel="icon" href="../favicon.svg">` を付ける
- OGP（`og:type`、`og:site_name`、`og:locale`、`og:title`、`og:description`、`og:url`、`og:image`）と `twitter:card` を付ける。`og:image` は `ogp/フォルダ名.png`（1200×630）を用意する。既存の画像と同じ見た目で作る
- 構造化データ（JSON-LD）として、`WebApplication`、`BreadcrumbList`、`FAQPage` を入れる。内容は画面に表示している文章と一致させる

### 本文
- `h1` はツール名の1つだけにする
- ツールの下に、`shared.css` の `.guide` を使って次の3つを置く
  - 「使い方の例」：2件程度。入力・設定・結果を書き、**結果は実際にツールで実行して確かめたもの**にする
  - 「よくある質問」：3〜5件。実際の動作と食い違うことを書かない
  - 「ほかのツール」：公開済みのほかのツールへのリンク
- 新しいツールを公開したら、既存のツールの「ほかのツール」にも追加する

### サイト全体
- `sitemap.xml` に、新しいツールのURLと更新日（`lastmod`）を追加する。既存ページを変更したら、その `lastmod` を更新する
- トップページのツール一覧と、トップページの構造化データ（`ItemList`）に追加する
- 内部資料（README など）は公開しない。公開したくないMarkdownファイルは `_config.yml` の `exclude` に追加する

### 広告（運営が準備できてから）
- アフィリエイトのリンクには `rel="sponsored noopener"` を付け、「広告」または「PR」と表示する
- ツールのページには、外部のスクリプトを読み込む広告を入れない（入力内容を読み取れてしまうため）。スクリプト型の広告はトップページのみ
